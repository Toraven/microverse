# MEMORY.md — Повторяющиеся паттерны ошибок

Этот файл ведётся автоматически. Фиксируются ошибки, которые встречались более одного раза,
чтобы не повторять их в будущих итерациях.

---

## [JSX] Незакрытый фрагмент при условном рендере

**Паттерн:**
Открыть условный фрагмент `{condition&&<>` и забыть закрыть его `</>}` перед следующим
условным блоком или концом return.

**Пример ошибки (из сессии 2026-02-24):**
```jsx
// НЕПРАВИЛЬНО — фрагмент не закрыт
{!protocolMode&&<>
  <FilterRowA/>
  <FilterRowB/>

{/* Cards grid */}
{filtered.length===0 ? ... : ...}
</div>   // ← JSX parse error: missing closing tag for fragment
```

**Правильно:**
```jsx
{!protocolMode&&<>
  <FilterRowA/>
  <FilterRowB/>
  {/* Cards grid */}
  {filtered.length===0 ? ... : ...}
</>}

{protocolMode&&(
  <ProtocolView/>
)}
```

**Диагностика:**
- `JSX element has no corresponding closing tag`
- `Expected corresponding closing tag for JSX fragment`
- `Unexpected token. Did you mean {'>'} or &gt;?`

**Правило:** Всегда закрывать фрагмент ДО добавления следующего условного блока.
Если несколько блоков условны по одному флагу — оборачивать все вместе.

## [JSX] Порядок: сначала читать файл, потом вставлять

**Паттерн:**
Вставить фрагмент кода в середину файла без предварительного чтения окружения →
нарушение структуры вложенности.

**Правило:** Перед каждой вставкой читать ±30 строк контекста вокруг точки вставки.

## [PLAN] Несколько взаимозависимых изменений в одном файле

**Паттерн:**
Применять изменения к одному и тому же файлу последовательно несколькими `Edit` вызовами
без проверки диагностики между ними → ошибки накапливаются и мешают друг другу.

**Правило:**
1. Сначала сделать все изменения, которые не пересекаются структурно.
2. После изменений, затрагивающих JSX-структуру (условные блоки, фрагменты) —
   сразу вызвать `getDiagnostics`.
3. Если есть ошибки — исправить до следующего шага.

## [STATE] Новые useState хуки в компоненте

**Паттерн:**
Добавлять новый state в компонент и не проверять, что он используется в обоих ветках
рендера (list view / detail view).

**Пример (2026-02-24):**
`protocolMode` и `activeScenario` добавлены в `MediaLabTab`, но detail view их игнорирует —
это нормально, т.к. detail view рендерится вместо list view полностью. Проверять нужно
только то, что state сбрасывается при необходимости (например, `setProtocolMode(false)`
при открытии detail view — если требуется).

## [DATA] IDs в PROTOCOLS не совпадают с media.js

**Паттерн:**
Прописать ID среды в `PROTOCOLS[].primary/confirmatory/resistance`, которого нет в `MEDIA`.
Результат: `MEDIA.find(m=>m.id===id)` возвращает `undefined`, карточка молча пропускается
через `.filter(Boolean)`.

**Правило:** После добавления нового протокола проверять все ID через:
```js
PROTOCOLS.flatMap(p=>[...p.primary,...p.confirmatory,...p.resistance])
  .filter(id=>!MEDIA.find(m=>m.id===id))
// должен вернуть []
```

## [TRANSLATION] Ключ есть в одном языке, нет в другом

**Паттерн:**
Добавить ключ в `T.ru`, забыть продублировать в `T.en` (или наоборот).
В рантайме → `t.someKey` возвращает `undefined`, рендерится пустое место.

**Правило:** Добавлять ключи всегда парно: сначала в ru-блок, сразу следом в en-блок.
Шаблон для проверки:
```js
Object.keys(T.ru).filter(k=>!T.en[k])  // должен вернуть []
Object.keys(T.en).filter(k=>!T.ru[k])  // должен вернуть []
```
